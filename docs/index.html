Wireless Chip Buying Brief

Which Wireless Chip Should A Product Manager Bet On?

This homepage should answer the real buying questions behind wireless chip selection: which protocols matter for the target product, which competitors are strongest in that segment, which OEM requirements are forming next, how fast standards are moving, and whether the software stack and ecosystem are strong enough to reduce launch risk. Use this page as the front door for shortlist creation, positioning, roadmap pressure-testing, and executive discussion.

Buyer Cockpit

Use this sequence to make a chip-selection call quickly: filter by product fit, score likely winners, then decide where to spend validation effort.

What This Page Should Answer

Question 1

Does the chip fit the product and protocol mix?

Start with protocol fit: Bluetooth, Wi-Fi, Thread, Zigbee, Matter, 802.15.4 or Aliro. The wrong connectivity foundation forces expensive board and software rework later.

Question 2

Can we win against the incumbent vendor?

Look at which competitors are strongest in the exact application you care about, what they claim as strengths, and which gaps they are still exposed on.

Question 3

Are OEM requirements moving under us?

Customer launch signals tell you what features will matter next: LE Audio, mesh robustness, low power, coexistence, security certifications, range, or software portability.

Question 4

Will the software stack shorten time-to-launch?

Protocol support alone is not enough. PMs should test whether the stack, examples, certifications, partner ecosystem and developer tooling reduce execution risk.

Question 5

Is the roadmap aligned with the next two years?

Standards timing matters. If the chip roadmap misses the next meaningful protocol features, the design can age out before volume ramps.

Which Protocol Roadmaps Matter

This section tells PMs whether the chip roadmap is aligned with the next standards wave or whether the portfolio risks being one spec cycle late.

Bluetooth

Now: Bluetooth Core Specification 6.3 (adopted) Next: Not yet announced (6.3 is the latest adopted release)
  • Channel Sounding Inline PCT Transfer (BT 6.3) — analog phase pre-compensation for faster, lower-overhead ranging
  • Channel Sounding PHY-specific RTT Accuracy (BT 6.3) — per-PHY ranging precision (LE 1M/2M)
  • Running Out of Bits (BT 6.3) — expanded HCI command/event bitmask for future feature growth

AIROC CYW20829 ships Channel Sounding (PBR/RTT baseline from BT 6.0); CYW55513 covers LE Audio. Track BT 6.3 Channel Sounding refinements (Inline PCT Transfer, per-PHY RTT) for next silicon revs.

Wi-Fi

Now: Wi-Fi 7 (802.11be) certified Q1 2024 Next: Wi-Fi 8 (802.11bn) draft, target 2028
  • Wi-Fi 7 MLO mass deployment in routers/clients
  • Wi-Fi 8 UHR — Ultra-High Reliability (deterministic, mobility)
  • AFC (Automated Frequency Coordination) for 6 GHz standard power

AIROC CYW5557x (Wi-Fi 6E + BT 5.4) competing with Qualcomm/MediaTek/Realtek. No Wi-Fi 7 announced yet — gap vs Synaptics Veros/MediaTek Filogic 380.

802.15.4

Now: IEEE 802.15.4 baseline in active low-power mesh deployments Next: Incremental profile updates driven by ecosystem layers
  • Low-power PHY/MAC baseline used under Thread/Zigbee mesh ecosystems
  • Channel agility and robust coexistence remain central for dense IoT deployments
  • Interoperability outcomes depend on upper-layer protocol/profile alignment

Infineon CYW55573 provides 802.15.4 support as the PHY/MAC base for Thread and Zigbee class networks.
