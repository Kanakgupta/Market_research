🧭 Technical Overview

The Zephyr Bluetooth subsystem is one of the most complete open-source Bluetooth implementations in existence. Unlike a bare HCI shim, it delivers the whole vertical: application APIs, the full Host protocol stack, a standards-compliant open Controller, and optional Mesh and LE Audio frameworks. It is designed to scale from a tiny single-core SoC (combined build) up to a multi-core or dual-chip design where Host and Controller run on separate processors and talk over HCI.

Complete & Qualified

A Bluetooth-qualified Host and Controller with maintained QDIDs, so a chip vendor can inherit qualification rather than build a stack from zero.

Modular via Kconfig

Every layer, profile and service is a Kconfig option. Builds are tailored to flash/RAM budget — from a beacon in a few KB to a full LE Audio hearing aid.

Vendor-Neutral

Not tied to any silicon vendor. The same API runs on Nordic, NXP, TI, Silicon Labs, ST, Renesas, Ambiq and simulation targets.

Permissive License

Apache-2.0 across the tree — royalty-free, no copyleft obligations on product firmware, friendly to commercial productization.

Test-First

Extensive CI: unit tests, the BabbleSim (bsim) radio simulator for full end-to-end link testing, and Auto-PTS integration for SIG test suites.

Leading-Edge Spec

Tracks the newest Core features — Extended/Periodic Advertising, LE Coded PHY, Isochronous Channels (ISO), Connection Subrating and Channel Sounding work in progress.

Why it matters for a chip provider: Zephyr lets a silicon team ship a credible, upgradable, standards-tracking Bluetooth solution without funding a full proprietary stack team — while still differentiating through their own Controller/radio, power optimizations and value-add profiles.

🏗️ Architecture & Build Topologies

Bluetooth is split by the specification into a Host and a Controller, connected by the Host Controller Interface (HCI). Zephyr implements both sides and lets you place the HCI boundary wherever your hardware design needs it.

Application & Profiles
Your firmware + GATT-based profiles/services, Mesh models, or LE Audio use-cases built on the public <zephyr/bluetooth/*.h> APIs.
Host — subsys/bluetooth/host
GAP, GATT/ATT, L2CAP (incl. LE Credit-Based Channels), SMP (pairing, bonding, LE Secure Connections), ISO, key management and the HCI core driver.
HCI — Host Controller Interface
Standard command/event/data boundary. Can be in-process (combined build) or over a physical transport (UART / SPI / USB / IPC between cores).
Controller (Link Layer) — subsys/bluetooth/controller
Open-source LL: advertising, scanning, connections, channel selection, encryption, extended/periodic adv, ISO streams. Also runs as an HCI controller for external hosts.
Radio Hardware Abstraction / PHY
Vendor radio drivers below the LL; on simulation this is BabbleSim’s virtual 2.4 GHz medium.

1. Combined (single-chip)

Host + open Controller on one SoC. Smallest BOM, most common for wearables/sensors. HCI is an internal software interface.

2. Host-only (HCI over transport)

Zephyr Host talks to an external Bluetooth controller over UART/SPI/USB. Lets you pair the Zephyr Host with a vendor radio.

3. Controller-only (network co-processor)

Zephyr open Controller exposed via hci_uart/hci_usb so another host (Linux/BlueZ, another MCU) drives the radio.

This split is the single most strategically important property: it decouples the value-add software (Host, profiles) from the differentiated silicon (Controller, radio, power), and it is exactly how downstream vendor SDKs are built.

🎧 LE Audio — Generic Audio Framework

The audio/ subsystem is a full implementation of the LE Audio profile stack on top of ISO + LC3, enabling hearing aids, earbuds, TV/broadcast audio and Auracast™ assistants. Each acronym below is a real profile/service directory in the tree.

BAP

Basic Audio Profile — unicast & broadcast stream establishment, codec/QoS config, the foundation of LE Audio.

CAP

Common Audio Profile — coordinated procedures across a set of devices (e.g. left+right earbuds) for interoperable behavior.

VCP / MICP

Volume Control & Microphone Control profiles — synchronized volume/mute across a device set.

CSIP

Coordinated Set Identification — how a phone discovers that two earbuds are one logical set.

MCP / MCS

Media Control — play/pause/track control of a media player from a headset.

TBS / CCP

Telephone Bearer & Call Control — answer/hang-up call control for headsets.

HAS / HAP

Hearing Access Service & Profile — presets and behavior specific to hearing aids.

TMAP

Telephony & Media Audio Profile — the end-to-end phone-call + media use-case bundle.

PBP

Public Broadcast Profile — the Auracast™ public broadcast layer on top of broadcast BAP.

GMAP

Gaming Audio Profile — low-latency bidirectional audio for gaming headsets.

BASS

Broadcast Audio Scan Service — the Broadcast Assistant that steers a device to a broadcast source.

LC3

Low Complexity Communications Codec integration — the mandatory LE Audio codec.

🕸️ Bluetooth Mesh

The mesh/ subsystem is a complete, qualified Bluetooth Mesh node implementation for large-scale lighting, sensor and building-automation networks.

Provisioning

Both PB-ADV and PB-GATT bearers; OOB authentication; the full node onboarding flow.

Foundation & models

Configuration & Health server/client, plus support for standard and vendor models (sensor, generic on/off, level).

Roles & power

Relay, Proxy, Friend and Low Power Node (LPN) features for battery-operated mesh devices.

Mesh DFU + BLOB

BLOB Transfer and Device Firmware Update models for firmware distribution over the mesh.

✅ Certification & Qualification

Zephyr’s Bluetooth Host and Controller are qualified with the Bluetooth SIG, and the project maintains the test infrastructure needed to keep that qualification current.

Bluetooth SIG Qualification

The Host and Controller carry maintained QDIDs/Design listings. A product using the Zephyr subsystem can reference the component qualification and complete its own end-product listing, dramatically reducing certification cost and time.

Auto-PTS

Automated integration with the SIG Profile Tuning Suite (PTS) so profile/host behavior is continuously validated against official test cases.

BabbleSim (bsim)

A physical-layer simulator that runs real Host+Controller firmware against a virtual radio medium — enabling full multi-device link, ISO and mesh test scenarios in CI without hardware.

Conformance & CI

Unit tests, integration tests and hardware-in-the-loop runs gate every change; regressions in the stack are caught before merge.

Qualification specifics (QDID numbers, listed features) change per release — always confirm the exact listing on the Bluetooth SIG Qualification Workspace for the Zephyr version you ship.

♟️ Strategy Playbook for a Chip Provider

How different teams should read the Zephyr Bluetooth stack when building a silicon go-to-market and developer-support strategy.

📈 Product Marketing

  • Position Zephyr support as “standards-tracking, royalty-free, future-proof” to reduce customer lock-in fears.
  • Inherited SIG qualification is a hard cost/time saving — quantify it in the value prop.
  • LE Audio + Auracast™ readiness is a premium differentiator for audio SoCs.
  • Membership tier (Platinum vs Silver) signals influence over the roadmap — use it as a trust marker.

🛠️ Application / Developer Marketing

  • Lead with the 60+ samples and the Bluetooth shell — time-to-first-blink is a conversion metric.
  • Publish board-specific getting-started guides mapped to Zephyr sample names.
  • Contribute your board/driver upstream so evaluators find you in the supported-boards catalog.
  • BabbleSim lets developers evaluate before hardware arrives — promote hardware-free trials.

🔬 Engineering / Ecosystem

  • Decide the HCI split: open Controller on your radio vs Zephyr Host over your controller.
  • Fund maintainer time to earn code-owner status in the areas you depend on.
  • Track ISO / Channel Sounding / Subrating work to time feature announcements.
  • Keep your downstream SDK rebased on LTS (v3.7.0) for stability, main for leading edge.

⚠️ Risks & Watch-items

  • Some Classic (BR/EDR) profiles are less mature than BLE — verify per use-case.
  • Qualification is per-release; a version bump can require re-confirming the listing.
  • Open Controller quality depends on the radio HAL you provide — budget for it.
  • Roadmap influence correlates with contribution — passive consumers get less say.

🚀 Build, Evaluate & Contribute

The end-to-end path from clone to upstream contribution.

1. Get the tree
Install west, run west init + west update to pull Zephyr and modules.
2. Build a sample
Flash samples/bluetooth/peripheral to a supported board, or run it on native_sim with BabbleSim.
3. Configure via Kconfig
Toggle CONFIG_BT_* options to enable exactly the roles, profiles and services you need.
4. Validate
Run bsim tests and, for profiles, Auto-PTS against the SIG test suites.
5. Contribute
Follow the contribution guidelines, sign off (DCO), pass CI + code-owner review, land upstream.
# build the peripheral sample for a board
west build -b your_board samples/bluetooth/peripheral
west flash

# or run the full stack on a virtual radio (no hardware)
west build -b native_sim samples/bluetooth/peripheral
